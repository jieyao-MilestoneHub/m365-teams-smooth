AI Change Court — 系統架構與 Demo 說明

把高風險的企業決策「送上法庭」：先蒐證、評估衝擊、提出可行方案或更安全的替代方案， 解析需要哪些人核准、收取裁決，才跨系統執行，並留下不可竄改的稽核軌跡。

引擎已完成 · 124 測試全綠 · verify.sh 13/0/3 · 只剩 environment + recording

一、這是什麼

它不是聊天機器人，也不是工作流巨集。它判斷一個決策是否安全到可以執行；當不安全時， 會明確拒絕並提出更安全的路徑。整個流程是一條可檢視的「法庭」管線，對外以 Microsoft 365 Copilot / Teams 的宣告式代理（Declarative Agent）為入口，透過 OAuth2 保護的 MCP 呼叫後端，最終以 Teams 的 Change Court 自適應卡片呈現與收取裁決。

角色對應：Prosecutor＝impact ・ Defender＝options ・ Clerk＝audit ・ Executor＝execute。 在 [verdict] 以 interrupt_before=["execute"] 暫停並落 checkpoint； 送出即返回，之後的 cast_verdict 由 checkpoint 還原續跑。

2.2 分層與 SOLID 邊界

mcp/ · api/ — 薄門面（thin façade）。MCP 工具/資源與 REST(僅 health) 都只轉呼叫 services，零商業邏輯。
services/ · agent/ — 單一商業層與 LangGraph 法庭。只依賴 ports/，不碰任何 SDK。
adapters/ — ports 的具體實作：整合（GitHub real + 6 mock）、持久化、知識、通知。real-vs-mock 由設定挑選（Open/Closed）。
domain/ — 純模型/列舉/錯誤，不 import 任何框架或 SDK（依賴反轉的底座）。

新增一個整合 = 一個 adapter 模組 + 一次註冊，不需改動 graph / services / REST / MCP。

2.4 關鍵機制（差異化所在）

機制說明主要檔案
持久裁決中斷於 verdict gate 落 checkpoint（以 thread_id 為鍵），送出立即返回；裁決可在另一個程序還原續跑——graph 從不長駐記憶體。agent/graph.py、agent/runner.py
Dry-run 是狀態欄位不是另一條程式路徑。BaseIntegrationAdapter 模板方法只在一處分支：DRY_RUN 走 _predict（零副作用），LIVE 走 _apply。adapters/integrations/base.py
裁決冪等在 service 以 verdict ledger 先「認領」再續跑；重複裁決回傳已記錄結果、不重跑——REST 與 MCP 行為一致。services/court_service.py
幻覺守門intake 把每個動作對照已註冊能力；不支援的動作（如 delete repo）拒絕、記錄、絕不規劃或執行。agent/nodes/intake.py
安全替代方案請求不安全時，options 產生取代原請求的更安全計畫（私有預覽取代 GA；最小權限 + 到期自動撤銷取代廣泛存取）。agent/planners.py、agent/nodes/options.py
知識接地（Microsoft IQ）impact 透過 KnowledgePort 取得帶引用的事實；本地用離線 fake，設定端點後改用 Azure AI Foundry（Foundry IQ），零程式變動。adapters/knowledge/foundry_iq.py

四、DEMO 方式

4.1 本地 Demo（免租戶、免任何憑證）

整套以 FORCE_ALL_MOCK 在本機跑完三大審判，以 Customer Promise 的「拒絕」開場 （Customer Promise → Vendor Access → Launch Slip）：

cd backend && uv sync                 # 安裝相依
make demo                              # 三大審判；以拒絕不安全承諾開場
scripts/verify.sh                      # 全閘門驗證（下方輸出）

make demo 的「Customer Promise」段落（節錄，展示差異化的拒絕＋安全替代）：

=== Customer Promise ===
  > promise Customer A that SSO is GA by 2026-06-17
  status=awaiting_verdict  risk=high  unsafe=True
  plan: safe_alternative
    rationale: Reject the GA promise: offer a private preview on 2026-06-17,
               with GA pending the security review on 2026-06-18.
    - github.comment_issue
    - outlook.create_event
    - crm.add_note
    - outlook.draft_email        # 客戶信只產生草稿，不寄出
    - teams.create_escalation_thread
    grounded: A capability cannot be declared generally available before its
              security review completes. (GA Readiness Policy §2.1)
  approvers: security_lead, account_owner
  verdict options: ['accept_alternative', 'request_revision', 'reject']
  -> verdict accept_alternative: status=done  audit=…

4.2 透過 MCP 介面 Demo（與宣告式代理相同的呼叫面）

cd backend && uv run uvicorn app.asgi:app   # REST(/api/health) + OAuth2 MCP(/mcp)

MCP 工具的呼叫順序即一次完整審判： submit_change → 取得 thread_id 與摘要 → get_trial 看完整法庭 → cast_verdict（不安全案用 accept_alternative）→ done。 此流程已由 tests/test_mcp_tools.py 端到端驗證。

4.3 租戶 Demo（環境就緒後 — 即真正的展示畫面）

  1. 設定 OAUTH_*（連 Entra）、選用 KNOWLEDGE_*（Foundry IQ）、選用 GITHUB_TOKEN/GITHUB_REPO。
  2. 用 dev tunnel 把 app.asgi:app 的 /mcp 對外（公開 HTTPS），URL 填入 m365/ai-plugin.json 與 manifest.json 的 ${{…}}，補上 color.png/outline.png。
  3. 在開了 custom-app upload 的 M365 dev 租戶 sideload m365/ 的宣告式代理。
  4. 於 Copilot Chat / Teams 輸入任一審判請求 → Change Court 卡片渲染（衝擊、計畫/安全替代、核准人、裁決按鈕）→ 按裁決鈕觸發 cast_verdict，由 checkpoint 還原續跑並回傳結果卡。

關鍵：上述每一步都是設定與安裝。程式端的接點（JWKS 驗證、Foundry IQ、real GitHub）皆已寫好， 由環境變數在現有 seam 上自動切換，無需再寫引擎程式碼。
