① Layered container architecture

One deployable backend, strict dependency inversion: the decision core never touches an SDK, and every integration is a plug-in behind a port.

What this view shows

A container-level (C4) view of the whole system. Requests enter from Microsoft 365 Copilot Chat / Teams through a declarative agent, reach a single FastAPI process over MCP with OAuth 2.0, and flow down through thin façades into one business layer, the LangGraph court, and — only via abstract ports — out to the integrated systems. The Change Court Adaptive Card is the decision UI; the one web surface is a read-only, signed-link run page.

Design rationale

  • Dependency inversion as the load-bearing wall. The decision core (services/ and agent/) depends only on abstract ports; all SDK, database, and LLM specifics are quarantined in adapters/. Swapping a real system for a mock — or adding a brand-new integration — is a configuration and adapter concern, never a change to the court itself.
  • One business layer, many surfaces. MCP tools, REST, and the card actions are deliberately thin. Every rule — separation of duties, idempotency, risk gating — lives exactly once in services/, so no surface can drift into a privileged or inconsistent path.
  • A pure domain vocabulary. Change, Verdict, Quorum, AuditRecord are plain models with no framework imports. The courtroom language stays portable, serializable, and trivially testable.
  • Mock-first integrations. GitHub is the one real adapter; the other six return realistic, seeded evidence. The full pipeline — including refusals and approvals — runs on a laptop with zero external credentials.
  • No dashboard by design. Decisions happen on the Adaptive Card where the conversation is; the only web surface is a read-only run page behind signed links. There is no second UI to govern or to drift.

Key guarantees

  • The core never imports an integration SDK, an ORM, or an LLM client — only ports.
  • Adding an integration touches one new adapter and one registration; the graph, services, REST, and MCP stay untouched (open/closed).
  • Real-vs-mock is chosen per system from configuration, with a kill-switch that forces everything to mock for credential-free runs.
  • Every surface resolves to the same business layer — identical behavior from the card, MCP, or REST.
