AI Change Court — 架構圖

把高風險的企業決策送上法庭：蒐證 → 評估衝擊 → 提出可行方案或更安全的替代 → 解析核准人 → 收取裁決 → 執行 → 留下不可竄改的稽核。本頁為自包含靜態 HTML,離線即可開啟。

五張圖由外而內、由流程到資料:① 分層容器架構 ② 法庭管線與治理自治分割 ③ 職責分離審批時序 ④ 安全與信任邊界 ⑤ 持久化與資料模型。每張圖採單向流向、每層一色、附圖例。

① 分層容器架構(C4 container 級)

依賴反轉:agent/、services/ 只依賴 ports/;具體實作在 adapters/;domain/ 不 import 任何框架或 SDK。新增整合 = 一個 adapter + 一次註冊。

M365 入口 門面 mcp/api 核心 services/agent ports(DIP 邊界) adapters domain(純) 持久化

② 法庭管線與治理自治分割

一條可檢視的 LangGraph 圖,角色化呈現。代理的自由在感知與生成(藍); 安全裁決恆為確定性(綠)。裁決是持久中斷(橘),送出即返回、由 checkpoint 還原續跑。

Agentic(有 LLM 時推理,失敗回退確定性) 確定性治理(永不交給 LLM) 持久中斷 / 裁決閘

③ 職責分離審批時序

提案人不能核准自己的變更;核准人由設定的 ApproverDirectory 解析。時間由上而下。

④ 安全與信任邊界

每道防線標出其位置:認證在 MCP 邊界、授權在服務層、參數驗證在 adapter 邊界、稽核不可竄改。

守門 / 拒絕 認證邊界 完整性 / 邊界值
