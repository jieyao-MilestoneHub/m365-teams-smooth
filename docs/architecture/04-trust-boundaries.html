What this view shows

The four defense lines a request crosses on its way to an external system, plus the two integrity anchors beside them. Authentication happens once at the MCP boundary; authorization and resource bounds in the service layer; whatever an LLM proposes is checked against the registered capability catalog; and every adapter validates its parameters again at the final boundary before any API call.

Design rationale

  • Each boundary assumes the previous one failed. Authentication, authorization, capability checking, and parameter validation are independent lines, so a single bypass never reaches an external system unchecked.
  • The LLM is treated as untrusted input. Whatever it parses or proposes is validated against the registered capability catalog — name and parameter schema — before anything downstream sees it. A request to do something the system has no capability for (say, deleting a repository) is blocked at intake and recorded, not negotiated with.
  • Prompt injection is answered at the output, not the input. Sanitizing prompts is a losing game; constraining what any output is allowed to do — registered capabilities only, schema-validated parameters, traversal-safe paths — is enforceable.
  • Reject, don't truncate. Oversized input is refused outright. Silent truncation would let a request mean something other than what was reviewed.
  • Keyless where the platform allows. Azure services authenticate via managed identity, so there is no long-lived key to rotate or leak; remaining secrets live in the host's secret store, never in the repository or logs.

Key guarantees

  • No valid token, no entry — and the token's claims, not the caller's say-so, become the Principal that every later gate trusts.
  • An action outside the registered catalog can be neither planned nor executed.
  • Audit rows are never updated; rollback hints are advisory data and are never auto-executed.
  • Live writes are explicitly gated; dry-run and the all-mock kill-switch are always available.
  • Run budgets (tokens, timeouts, retries, graph wall-clock) cap the blast radius of any misbehaving run.
