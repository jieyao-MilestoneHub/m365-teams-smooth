② Court pipeline & governed autonomy

One inspectable graph, courtroom roles, and a hard split: the agent reasons in blue, governance decides in green, and the human verdict is a durable interrupt in orange.

What this view shows

The court is a single LangGraph pipeline presented as courtroom roles: the Prosecutor gathers impact evidence, the Defender drafts a feasible plan — or a safer alternative when the request is unsafe — the Clerk keeps the record, and the Executor carries out the approved steps. The agent's freedom lives in perception and generation (blue); the safety verdict is always deterministic (green). The verdict itself is a durable interrupt (orange): submitting returns immediately, and a later verdict rehydrates the run from its checkpoint.

Agentic (reasons when an LLM is configured; falls back to deterministic) Deterministic governance (never delegated to the LLM) Durable interrupt / verdict gate

Design rationale

  • Roles, not separate agents. Prosecutor (impact), Defender (options), Clerk (audit), and Executor (execute) are nodes of one graph today — inspectable end to end. Because every node is state-in/state-out, the same roles can later become cooperating agents behind a registry without rewriting the pipeline.
  • Governed autonomy. The model may choose which evidence to read (bounded to a small read budget) and how to phrase a plan, but risk scoring, quorum resolution, refusal binding, and execution gating are data-driven rules. The creative parts are swappable; the safety parts are reproducible.
  • The verdict is a durable interrupt. A human decision can take hours or days. The run suspends to a checkpoint before execute and nothing is held in memory across the gap — any process restart, scale-out, or redeploy is safe while a verdict is pending.
  • Refusal is a product feature, not an error. When the evidence marks a request unsafe, the Defender's output is a safer counter-proposal — least privilege, a conflict-free date, a narrower scope — and the verdict options change accordingly (no plain approve).
  • Precedents are explainable memory. Closed trials are summarized and cited by subject and tag overlap — retrieval the audit can explain, not an opaque embedding store.

Key guarantees

  • An action with no registered capability is blocked at intake — never planned, never executed.
  • Casting the same verdict twice returns the recorded result; execution cannot happen twice.
  • If the LLM is absent or fails, every blue node falls back to its deterministic path — the trials stay reproducible fully offline.
  • Dry-run is a state field honored at execute: predicted effects, zero side effects, an audit record marked accordingly.
  • The verify step compares predicted against actual effects after execution, and the discrepancy report lands in the audit.
